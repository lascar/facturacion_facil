## 🐍 Principios de Código Pythonic - OBLIGATORIO ⚠️

### Filosofía general
- ✅ **Simple is better than complex** (Zen de Python)
- ✅ **Readability counts** - El código debe ser fácil de leer y entender
- ✅ **Explicit is better than implicit** - Ser claro en las intenciones
- ✅ **KISS**: Keep It Stupidly Simple - No sobrecomplicar
- ✅ Usar las fortalezas de Python: legibilidad, simplicidad, expresividad

### 1. Preferir Funciones a Clases - OBLIGATORIO ⚠️
- ✅ **REGLA**: Comenzar SIEMPRE con funciones
- ✅ **REGLA**: Añadir clases SOLO si aportan un valor real
- ❌ **PROHIBICIÓN**: Crear clases sin variables miembro
- ❌ **PROHIBICIÓN**: Crear clases que solo sirvan para agrupar funciones
- 💡 **EJEMPLO**: Si una clase solo tiene métodos y sin estado → usar funciones
- 🎯 **VENTAJA**: Más fácil de testear, más simple, menos boilerplate

### 2. Usar Context Managers - OBLIGATORIO ⚠️
- ✅ **OBLIGATORIO**: Usar `with` para abrir archivos
- ❌ **PROHIBICIÓN**: Abrir/cerrar manualmente los archivos
- 💡 **RAZÓN**: Gestión automática de recursos, incluso en caso de error
```python
# ❌ MAL
f = open('file.txt', 'r')
data = f.read()
f.close()

# ✅ BIEN
with open('file.txt', 'r') as f:
    data = f.read()
```

### 3. Anotaciones de Tipo - OBLIGATORIO ⚠️
- ✅ **OBLIGATORIO**: Añadir anotaciones de tipo a TODAS las funciones
- ✅ **OBLIGATORIO**: Anotar los parámetros Y los valores de retorno
- ✅ **OBLIGATORIO**: Anotar los tipos de colecciones (list[int], dict[str, Any], etc.)
- 💡 **VENTAJA**: Mejor legibilidad, detección de errores, ayuda del IDE
```python
# ❌ MAL
def process_data(items, count):
    return items[:count]

# ✅ BIEN
def process_data(items: list[str], count: int) -> list[str]:
    return items[:count]
```

### 4. EAFP vs LBYL - Preferir EAFP ⚠️
- ✅ **PREFERIR**: EAFP (Easier to Ask Forgiveness than Permission)
- ❌ **EVITAR**: LBYL (Look Before You Leap)
- 💡 **PRINCIPIO**: Probar primero, gestionar el error después
```python
# ❌ LBYL (menos pythonic)
if os.path.exists(file_path):
    with open(file_path) as f:
        data = f.read()

# ✅ EAFP (pythonic)
try:
    with open(file_path) as f:
        data = f.read()
except FileNotFoundError:
    print("Fichero no encontrado")
```

### 5. Dataclasses para Datos Estructurados - OBLIGATORIO ⚠️
- ✅ **OBLIGATORIO**: Usar `@dataclass` para las estructuras de datos
- ✅ **VENTAJA**: Menos boilerplate, generación automática de `__init__`, `__repr__`, etc.
- ✅ **USAR**: `field(default_factory=...)` para valores por defecto dinámicos
```python
from dataclasses import dataclass, field
from datetime import datetime

@dataclass
class Entry:
    description: str
    calories: int
    date: str = field(default_factory=lambda: datetime.now().strftime("%Y-%m-%d"))
```

### 6. Centralizar Constantes y Rutas - OBLIGATORIO ⚠️
- ✅ **OBLIGATORIO**: Definir las constantes en la PARTE SUPERIOR del archivo
- ✅ **OBLIGATORIO**: Usar `pathlib.Path` en lugar de strings para las rutas
- ✅ **CONVENCIÓN**: Constantes en MAYÚSCULAS
```python
from pathlib import Path

# ✅ BIEN - En la parte superior del archivo
FOOD_CSV = Path("data/food.csv")
ACTIVITY_CSV = Path("data/activity.csv")
MAX_RETRIES = 3
```

### 7. Explotar las Fortalezas de Python - OBLIGATORIO ⚠️
- ✅ **USAR**: Comprensiones de listas en lugar de bucles
- ✅ **USAR**: Generadores (`yield`) para grandes cantidades de datos
- ✅ **USAR**: Iterators en lugar de listas cuando sea posible
```python
# ❌ MAL
result = []
for item in items:
    if item > 0:
        result.append(item * 2)

# ✅ BIEN
result = [item * 2 for item in items if item > 0]

# ✅ AÚN MEJOR (para grandes datos)
def process_items(items):
    for item in items:
        if item > 0:
            yield item * 2
```

### 8. Logging en lugar de Print - OBLIGATORIO ⚠️
- ✅ **OBLIGATORIO**: Usar `logging` para los mensajes de debug/info
- ❌ **PROHIBICIÓN**: Usar `print()` para el logging
- ✅ **EXCEPCIÓN**: `print()` aceptable para los resultados finales del programa
```python
import logging

logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(levelname)s - %(message)s')
logging.info("Procesamiento iniciado")
```

### 9. Función Main - OBLIGATORIO ⚠️
- ✅ **OBLIGATORIO**: Encapsular el código principal en una función `main()`
- ✅ **OBLIGATORIO**: Usar `if __name__ == "__main__":`
- 💡 **VENTAJA**: Evita la polución del namespace global, facilita los tests
```python
def main() -> None:
    """Punto de entrada principal del programa"""
    # Código principal aquí
    pass

if __name__ == "__main__":
    main()
```
